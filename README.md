# Drawing QA Agent

**An AI drawing-set reviewer. It checks a drawing package against its brief, separates "rule failed" from "needs human review", and never edits drawings.**

Built by Ar. Vaibhav Patidar (architect; M.BEM, SPA New Delhi). Rule it is built on: **AI proposes, code checks, people approve.**

[Project 1 (AEC-Eval-30)](https://github.com/vaip04/AEC-Eval-30) measures where AI coworkers fail; Project 2 (drawing-qa-agent) builds the guardrail.

---

## What it does
Give it a drawing package: the project brief, the area statement, room geometry, the sheet index with callouts and revisions, and the door and window tags and schedule. It then:

1. Runs **13 checks in plain Python** (`src/checks.py`): area statement vs room polygons, area arithmetic, required rooms, minimum areas, built-up area and coverage limits, sheets drawn on an old brief, broken callouts, door/window tags vs schedule, sheet-index vs title-block revisions, undimensioned rooms, room-name variants, overlaps and very narrow rooms.
2. In **AI mode**, a **LangChain tool-calling agent** (`src/agent.py`) is given those checks as tools. The model decides which tools to call, LangChain runs them, and the model writes the review: one plain sentence per finding plus a 3-line summary for the architect.
3. A **code guardrail** then compares the model's review with what the tools actually returned:
   - a finding no tool produced is **dropped** and logged;
   - if the model changed a finding's rule, group, element, sheet or evidence, the tool's values are **restored** and the change is logged;
   - if the model skipped a check, the code **runs it anyway** and logs that.
4. Writes `findings.csv`, an HTML report and an annotated plan for each package.

Every finding has a rule ID, sheet number, element, evidence and severity, grouped as **RULE FAILED** (objective, measured in code) or **NEEDS HUMAN REVIEW** (design intent or interpretation).

```
drawing package ─► 13 checks (Python) ─► LangChain agent calls them as tools ─► model writes the review
                                │                                                    │
                                └──── ledger of real findings ───► guardrail ◄───────┘
                                                                     │
                                         findings.csv · report.html · plan_annotated.png
```

## Results
Full, current numbers are in [`outputs/eval.md`](outputs/eval.md), generated by `evaluate.py`. Deterministic mode:

| Test set | Planted errors | Caught | Missed | False flags |
|---|---|---|---|---|
| `demo_clean` (control, no errors) | 0 | 0 | 0 | 0 |
| `demo_seeded` | 12 | 12 | 0 | 0 |
| `demo_mixed` (different layout) | 6 | 6 | 0 | 0 |

An error counts as caught only when the right rule fires **on the right element** (an error spanning two sheets must be flagged on both). Design-intent traps in `demo_seeded` (a “Mstr Bed” name variant and a 3.5:1 passage) land in NEEDS HUMAN REVIEW, not in failures. **LLM mode not yet benchmarked.** A live run is needed to measure guardrail drops.

**Read these numbers carefully:** the test packages are synthetic and were written together with the checks, so they show the checks work as designed, not that they generalise to real drawing sets.

## How to run
```bash
git clone https://github.com/vaip04/drawing-qa-agent.git
cd drawing-qa-agent
python -m venv .venv
# Windows: .\.venv\Scripts\Activate.ps1     macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

python run.py --all --no-llm          # deterministic review of every package (no API key needed)
python evaluate.py --no-llm           # score against the answer keys
pytest -q                             # 46 tests, including the agent and guardrail (uses a fake model, no key needed)
streamlit run app.py                  # simple review page
```
**AI mode:** copy `.env.example` to `.env`, add a free Gemini key from Google AI Studio, then:
```bash
python run.py --package demo_seeded   # one package with the agent
python evaluate.py                    # both modes; writes outputs/eval.md
```
If the model name stops working, set `GEMINI_MODEL` in `.env` to any current Gemini model. If the AI step fails, the report says **"LLM FAILED, deterministic only"**; it never hides a failure.

## Files
| Path | What it is |
|---|---|
| `src/checks.py` | The 13 rule checks; each returns findings with a stable ID |
| `src/agent.py` | LangChain tool-calling agent and the guardrail |
| `src/loader.py`, `src/report.py` | Read a package; write the HTML report and annotated plan |
| `run.py`, `evaluate.py`, `app.py` | Command line, scoring, Streamlit page |
| `make_packages.py` | Generates the three synthetic test packages and their answer keys |
| `import_prototype.py` | Builds a test package from my architecture prototype's space standards (findings unverified) |
| `rules.yaml` | Tolerances you can change without touching code |
| `tests/` | Per-rule tests, agent/guardrail tests with a fake model, evaluator tests |

## Limitations
- Synthetic, simplified 2D packages (rectangles and tables), not real CAD/BIM files.
- Thresholds are project rules from the brief, **not** statutory code checks (NBC or bye-laws).
- Small test set; single run per mode.
